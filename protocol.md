# Verity Hackathon Eval Protocol

Nov 23, 2026 · @Lakshmi Manmohan

## Scope

The test asks one question: can Verity resolve borderline record pairs as well as a frontier LLM, at lower cost and latency? Target products are DIS Data Quality and MDM matching, or AI Studio. Every option runs on the same candidate pairs, generated by Verity's ANN blocking.

| Option | What decides a borderline pair |
| --- | --- |
| A. Threshold only | Verity's effective threshold |
| B. Frontier LLM (baseline) | LLM yes/no on the record pair |
| C. Classical ML | Gradient-boosted trees on per-field similarities, calibrated confidence |
| D. Hybrid | C, with pairs below a confidence cutoff sent to the LLM |
| E. SLM / cross-encoder | Small open-weight model, self-hosted |

## Evaluation set

A synthetic B2B organization dataset of about 10,000 records, generated with a new seed that was never used for tuning. No customer, personal or confidential data.

- **Labels:** ground-truth entity IDs from the generator, so no labels come from an LLM. 100 pairs are hand-checked and agreement is reported.
- **Seeded hard cases:** acronyms, truncated names, PO Box vs street address, same name at a different address.
- **Split:** borderline pairs go 60% train (for C only) and 40% held-out test. All options are scored on the test split only.
- **Reporting:** results for the full test split, plus the hard-case slice and the easy slice separately.

## Borderline definition

A pair is borderline when its weighted similarity falls within ±0.05 of the effective threshold. The effective threshold is max(learned threshold, 0.82). With a 0.82 threshold, the band is 0.77 to 0.87.

Pairs above the band are matches and pairs below it are non-matches for every option. The band is fixed before any option is scored and is not tuned afterward. The threshold stability fix (low cluster mean + 2 std dev) is applied before the band is computed.

## Quality and latency bars

An option passes only if it meets every bar below. These are set on the date above, before any option is run.

| Bar | Threshold | Measured on |
| --- | --- | --- |
| Borderline accuracy | Within 2 points of the LLM baseline (B) | Test split, borderline pairs |
| Overall precision | ≥ 98% | All candidate pairs |
| Overall recall | At least 5 points above threshold only (A) | All candidate pairs |
| Confidence calibration (C, D) | Expected calibration error ≤ 0.05 | Test split |
| Latency per pair (C) | p95 ≤ 20 ms, feature extraction included | Single CPU core |
| Latency per pair (E) | p95 ≤ 200 ms | Hardware stated in results |
| LLM share (D) | ≤ 20% of borderline pairs sent to the LLM | Test split |

End-to-end pipeline time is reported separately for embedding, ANN, scoring, classifier and LLM calls, with and without a cold start.

## Volume and cost assumptions

Costs are reported at three daily volumes. The 3 candidates per record and 3% borderline share are starting assumptions, replaced by measured values from the eval run.

| Records/day | Candidate pairs/day | Borderline pairs/day |
| --- | --- | --- |
| 100,000 | 300,000 | 9,000 |
| 1,000,000 | 3,000,000 | 90,000 |
| 10,000,000 | 30,000,000 | 900,000 |

- **LLM cost per pair:** measured input and output tokens × the model's list price on the test date. Starting estimate is 500 input and 50 output tokens per pair.
- **Self-hosted cost:** instance hourly price × hours needed at the measured throughput, priced both always-on and serverless.
- **Who pays:** Precisely-hosted LLM cost lands on Precisely; with BYOK it lands on the customer. Both cases are shown.
- **Break-even:** the daily volume where self-hosted cost (or D's LLM share) equals the LLM-only cost.

## Fairness rules and limitations

Every option sees the same pairs, the same record fields and the same test split. Nothing is tuned on the test split.

- The LLM gets one fixed prompt, written before testing, with field names and values for both records. Prompt and model version are logged.
- The SLM is run zero-shot first. A fine-tuned version, if any, is reported as a separate row.
- Any option that fails a bar is still reported, with the bar it missed.
- **Limitations:** synthetic data may not reflect real customer noise. Results cover English B2B organization records only. Token counts and prices are measured on the test date and will change.

## Amendments

**Nov 23, 2026: evaluation seed changed from 2026 to 7919.** A full Verity run was made on data generated with seed 2026 and its metrics were viewed before any option was scored. Seed 2026 is now a development seed, alongside 42. The evaluation set is generated with seed 7919, which had not been used for any run when this note was written. No quality bar, the borderline band or any volume assumption changed.

**Nov 23, 2026: evaluation runs use exact neighbor search.** Candidate pairs for every option come from exact cosine nearest-neighbor search (`VERITY_NN_MODE=exact`), so they don't depend on whether Annoy is installed. This replaces "ANN blocking" in Scope as the source of candidate pairs. Approximate (Annoy) index build and query time is measured separately on the same data and reported for the cost model only. No quality bar, the borderline band or any volume assumption changed.

**Nov 23, 2026: three clarifications, made before any option was scored.**
1. The borderline band is centered on the effective threshold, max(learned threshold, 0.82), for every pair, including pairs with no shared field values.
2. "Weighted similarity" is the final pair score Verity writes to scored_pairs.csv. Band membership is decided by that score alone. Outside the band, every option uses Verity's own decision unchanged. Inside the band, each option makes its own decision.
3. The 60/40 split is made by connected component of the candidate-pair graph, so all pairs touching the same records land on the same side. The split seed is fixed at 0.

**Nov 24, 2026: split method replaced, before any option was scored.** Clarification 3 can't be followed: on development data, all candidate pairs, and all band pairs, form one connected component covering every record. The split is made by record instead. Records are grouped by connected component of the graph whose edges are Verity's matched pairs plus all pairs scoring above the band. Components are shuffled with seed 0 and assigned to train until train holds 55% of records, so about 60% of kept band pairs land in train. A pair is kept only if both of its records are on the same side. Pairs that cross the split are excluded from training and scoring. Every metric, including overall precision and recall, is computed only on pairs whose two records are both in the test group. The split uses no ground-truth labels.

**Nov 24, 2026: borderline bar changed from accuracy to F1, before any option was scored.** On development data, about 0.8% of test band pairs are true matches, so an option that always answers "different" scores about 99% accuracy, and the accuracy bar can't separate options. The bar becomes: borderline F1 (same-entity as the positive class) within 2 points of the LLM baseline (B), on test band pairs. Accuracy, precision and recall are still reported. F1 is reported with a bootstrap 95% interval (1,000 resamples, seed 0).

**Nov 24, 2026: LLM options scored on a fixed sample, before any LLM call.** With a total LLM budget of $30, options B and D can't be run on all ~45,000 test band pairs. They are scored on a fixed sample of 5,000 test band pairs: every same-entity pair plus non-matches drawn at random with seed 0, up to 5,000 pairs in all. Non-matches are weighted by the inverse of their sampling rate, so precision, recall and F1 estimate the full test band. Every option is reported on this sample, and the borderline F1 bar against B is judged on this sample, so the comparison is paired. Options A, C and E are also reported on the full test band. The bootstrap interval resamples within the sample, preserving the weights.

**Nov 24, 2026: correction to the LLM budget figure, before any LLM call.** The previous amendment states a total LLM budget of $30. The budget is $50 for all LLM spending, with a hard cap of $45 in the spending ledger. No other part of that amendment changes.
